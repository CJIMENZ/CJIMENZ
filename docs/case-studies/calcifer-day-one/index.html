What shipped

Calcifer started as a meeting recorder. For this experiment, I gave it a shared work board, four distinct Codex roles, and a digital office where I could see and talk to the team.

117 pull requests merged across four repositories in roughly 19 hours. Calcifer accounted for 102, and related projects accounted for 15. The count measures GitHub merges. Features, production deployments, and unattended work would each need their own measures.

PM, Dev, Review, and QA got separate identities and a shared record of the ticket, handoff, and evidence. Each role had a desk, the team could meet in the War Room, and the break room got a pool table.

How one ticket moves

  1. PM defines and assigns the work on the board.
  2. Dev claims it and links a pull request.
  3. Review checks the change before it merges.
  4. QA tests the deployed build and records the result.
  5. The owner closes the ticket with its evidence attached.

Calcifer stores the handoff for an eligible recipient. The team can compare delivery with pickup in the work log, while readers can discover work with read access.

What I’d measure next

Can one ticket get picked up without a nudge, return to the right role when a check fails, and reach deployed QA with an auditable record? Role connections and handoff storage shipped. Unattended pickup across the full path was still being validated.
